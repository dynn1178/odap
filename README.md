# 오답노크

> **두드리면 열릴지어다.**
> 오답 두드리기, 오답노크 — 간격반복(Spaced Repetition) 문제풀이 웹앱입니다.

- **스택**: Next.js (App Router, TypeScript) + Tailwind CSS
- **데이터**: Google Sheets (서비스 계정) — Sheets API 는 서버(Route Handler)에서만 호출
- **배포**: Vercel
- **설계 문서**: [오답노크_기획안_2.md](./오답노크_기획안_2.md)

---

## 1. 시작하기

### 1) 구글 서비스 계정 준비

1. [Google Cloud 콘솔](https://console.cloud.google.com/) → **API 및 서비스 > 라이브러리** → **Google Sheets API 사용 설정**
2. **사용자 인증 정보 > 서비스 계정 만들기** → 만든 계정의 **키 > 키 추가 > JSON** 다운로드
3. 스프레드시트를 하나 만들고, 우측 상단 **공유**에서 JSON 안의 `client_email` 주소를 **편집자(Editor)** 로 추가
   - 이 단계를 빼먹으면 `The caller does not have permission` 오류가 납니다. 가장 흔한 실수입니다.

### 2) 환경변수

```bash
cp .env.example .env.local
```

| 변수 | 어디서 얻나 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | 서비스 계정 JSON 의 `client_email` |
| `GOOGLE_PRIVATE_KEY` | 같은 JSON 의 `private_key` (큰따옴표로 감싸기, `\n` 그대로 둬도 됨) |
| `GOOGLE_SHEET_ID` | 시트 URL `.../spreadsheets/d/`**`여기`**`/edit` |
| `SESSION_SECRET` | 아무 랜덤 문자열 32자 이상 |
| `PIN_SALT_SECRET` | 아무 랜덤 문자열 32자 이상 — **한 번 정하면 바꾸지 마세요** (바꾸면 기존 PIN 이 전부 무효) |
| `CACHE_PURGE_TOKEN` | (선택) 캐시 강제 무효화용 토큰 |

랜덤 문자열은 이렇게 만들 수 있습니다:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

### 3) 시트 만들기

```bash
npm install
npm run setup:sheets
```

필요한 시트(`과목목록` `회원` `진도` `일별통계` `한줄남기기`)를 만들고 **한글 헤더**를 넣습니다.
과목목록이 비어 있으면 바로 돌려볼 수 있도록 **샘플 과목 + 샘플 문제 3개**도 넣어 줍니다.
이미 있는 시트에 빠진 컬럼이 있으면 **오른쪽 끝에 덧붙이기만** 하고, 기존 데이터는 건드리지 않습니다.
→ 앱을 업데이트한 뒤에도 이 명령만 다시 돌리면 됩니다.

### 4) 실행

```bash
npm run dev      # http://localhost:3000
```

첫 화면에서 **[처음이에요]** 로 이름 + 번호 4자리를 등록하면 바로 시작합니다.

## 2. 시트 구조

컬럼명은 모두 한글이고, 앱은 **열 순서가 아니라 1행 헤더 텍스트로 열을 찾습니다.**
→ 열 순서를 바꾸거나 메모용 열을 추가해도 앱은 그대로 동작합니다.
→ 헤더명을 바꾸고 싶으면 [`src/lib/sheets/schema.ts`](./src/lib/sheets/schema.ts) **한 곳만** 고치면 됩니다.

| 시트 | 컬럼 |
|---|---|
| `과목목록` | 과목코드 · 과목명 · 상위그룹 · 문제시트명 · 설명 · 노출순서 · 사용여부 · 양방향 |
| `문제_○○○` | 문제ID · 문제 · 정답 · 보기2~보기7 · 해설 · 사용여부 · 주관식 |
| `회원` | 회원ID · 이름 · PIN해시 · 솔트 · 가입일시 · 최근접속일시 |
| `진도` | 회원ID · 과목코드 · 진도데이터 · 갱신일시 |
| `일별통계` | 회원ID · 날짜 · 과목코드 · 푼문제수 · 정답수 · 오답수 · 학습시간초 · 난이도분포 |
| `한줄남기기` | 작성일시 · 회원ID · 과목코드 · 이름 · 내용 |

### 양방향 출제 (영단어 등)

`과목목록`의 **양방향** 칸에 `Y` 를 넣으면, **한 행에서 뒤집은 문제까지 냅니다.**

```
시트 1행:  호박 | pumpkin | carrot | March | scooter | swimming
             ↓
정방향:  "호박" → pumpkin      (시트에 적은 오답 보기)
역방향:  "pumpkin" → 호박      (다른 행의 한글 뜻에서 자동 추출)
```

- **역방향은 문제풀이 화면에서 [역방향] 또는 [섞어서] 를 직접 고를 때만 나옵니다.** 기본은 정방향이고, 고른 방향은 기기에 기억됩니다.
- 역방향 오답 보기는 **정답과 같은 언어**(한글/영문)끼리 뽑습니다. 문제ID 로 정해지므로 같은 문제는 늘 같은 보기를 받습니다.
- **학습 기록은 방향과 상관없이 한 문제로 합쳐집니다.** 진도 셀을 두 배로 쓰지 않으므로 단어를 최대 1,100개까지 넣을 수 있습니다.
- 같은 단어를 방향만 바꿔 두 행으로 넣어 두셨다면 **한 행만 남기세요.** 양방향을 켜면 나머지는 중복입니다.

### 주관식

`문제_○○○` 시트의 **주관식** 칸에 `Y` 를 넣으면 보기 대신 **입력창**이 나오고, 친 답을 채점합니다.

**정답을 여러 개 인정하려면** `정답` 칸에 `,` 또는 `;` 로 나열하세요. 어느 하나와 맞으면 정답입니다.

```
마흔, 40
eraser, rubber
지우개,고무지우개
```

채점 규칙:

| 정답 | 입력 | 결과 |
|---|---|---|
| `pumpkin` | `Pumpkin.` | ⭕ 대소문자·앞뒤 공백·문장부호 무시 |
| `아이스크림` | `아이스 크림` | ⭕ 띄어쓰기 차이 무시 |
| `마흔, 40` | `40` | ⭕ 나열한 정답 중 하나 |
| `베개` | `베게` | ⭕ **한 글자 오타는 넘어감** (화면에 알려 줍니다) |
| `eraser` | `erasr` | ⭕ 한 글자 오타 |
| `밤` | `밥` | ❌ 너무 짧아 오타로 안 봄 |
| `호박` | `수박` | ❌ |

오타 허용은 **자모 4개 이상**(한글 2음절 / 영문 4글자)일 때만 적용합니다.
한글은 자모로 풀어서 재기 때문에 `베개`(ㅂㅔㄱㅐ)와 `베게`(ㅂㅔㄱㅔ)는 오타로,
`밤`(ㅂㅏㅁ)과 `밥`(ㅂㅏㅂ)은 다른 단어로 구분됩니다.

- 주관식 행의 `보기2~보기7` 은 쓰이지 않습니다 (비워 두셔도 됩니다)
- **객관식 정답은 쪼개지 않습니다** — `서울, 대한민국` 같은 보기가 둘로 나뉘지 않습니다

### 문제를 추가하려면

1. `문제_○○○` 시트에 행을 추가합니다. **보기 개수는 문제마다 달라도 됩니다** (정답은 항상 1개, 빈 보기 칸은 자동 제외).
2. 새 과목이라면 시트를 하나 만들고 `과목목록`에 한 줄 등록하세요.
3. 문제은행은 **15분 캐시**됩니다. 시트를 고쳐도 바로 안 보이면:
   - 문제풀이 화면 오른쪽 위의 **[시트 다시 읽기]** 를 누르세요 (로그인 상태면 바로 됩니다)
   - 또는 `GET /api/cache/purge?token=<CACHE_PURGE_TOKEN>` (특정 과목만: `&key=questions:<과목코드>`)

   > **페이지 새로고침으로는 안 지워집니다.** 캐시는 서버 메모리에 있어서
   > 브라우저를 아무리 새로 고쳐도 15분이 지나거나 위 방법으로 지워야 반영됩니다.

### 과목당 문제 수 상한 — 1,100문제

진도는 (회원 × 과목)당 **셀 하나의 압축 문자열**로 저장하고, 구글시트 셀 한도가 **50,000자**입니다.
한 문제가 차지하는 길이는 `문제ID:score,streak,정답수,오답수,최근이력|` 이라 **문제ID 길이와 풀이 횟수**에 따라 달라집니다.

문제ID 8자(`Q1S4DJ9D`) 기준:

| 사용 정도 | 문제당 | 1,000문제일 때 | 한도까지 |
|---|---|---|---|
| 가볍게 (문제당 2~3회) | 21자 | 21,000자 (42%) | 약 2,380문제 |
| 보통 (문제당 10회 안팎) | 30자 | 30,000자 (60%) | 약 1,660문제 |
| 최악 (문제당 수백 회, 이력 꽉 참) | 35자 | 35,000자 (70%) | 약 1,420문제 |

→ **과목당 1,100문제까지는 어떤 경우에도 안전합니다.** 넉넉히 잡으려면 1,000문제로 두세요.
문제ID를 짧게 쓰면(예: 4자) 문제당 4자가 줄어 상한이 약 12% 늘어납니다.

**문제 수만으로는 경고하지 않습니다.** 개수는 실제 한계가 아니라서, 아무 문제도 없는데
매번 뜨는 잡음이었습니다. 대신 동기화할 때 **진도 셀의 실제 길이**를 재서
40,000자(한도의 80%)를 넘으면 그때 경고합니다 — 이건 진짜로 데이터가 잘릴 수 있다는 신호입니다.
분할 기준은 기획안 3-4를 참고하세요.

## 3. 화면 구조

```
/                    과목 선택 (여기서만 여러 과목이 보입니다)
                     └ 많이 푼 과목이 위로. 동점·미학습 과목은 시트의 노출순서를 따릅니다
└─ /study?subject=   문제풀이   ─┐  과목 안으로 들어오면
└─ /dashboard?subject=  대시보드 ─┘  이 과목 것만 보입니다
/settings            테마 · 글자 크기 · 폰트
/login               로그인 / 신규가입
```

**대시보드는 과목 하위 화면입니다.** 오늘 성적·누적 성적·추이·난이도 분포·출석·랭킹·방문자·한줄남기기가
모두 **선택한 과목 기준**으로만 집계되고, 다른 과목은 노출되지 않습니다.

### 대시보드가 보여주는 것

문제를 1,000개 나열하면 느리고 읽히지도 않아서, **"나아지고 있나"를 답하는 지표**만 보여줍니다.

| 블록 | 답하는 질문 |
|---|---|
| 나아지고 있나요? | 최근 7일 vs 직전 7일 — 정답률 / 하루 평균 학습시간 / 하루 평균 푼 문제 |
| 날짜별 추이 | 정답률·푼 문제·학습시간을 하나씩 골라 꺾은선으로 |
| 난이도 분포 | 지금 **마스터**(score 0) / **익숙**(1–3) / **노크 중**(4–10) / 아직 안 나옴 이 몇 개인지 |
| 날짜별 변화 | 그 분포가 날마다 어떻게 움직였는지 (초록이 자라고 빨강이 줄면 잘 되는 중) |
| 지금 자주 노크 중인 문제 | 상위 8개만 — 누르면 문제·해설·응답 경과를 봅니다 |

난이도 분포의 날짜별 변화는 **동기화할 때마다 그날 행에 스냅샷 한 칸**(`난이도분포`)으로 기록됩니다.
과거 데이터는 소급되지 않으므로, 이 기능을 올린 **다음 날부터** 그래프가 그려집니다.

## 4. 동작 방식 요약

### 출제 빈도

| 상황 | 버튼 | score 변화 |
|---|---|---|
| 정답 · 확실히 앎 | 쉽네 / 고고!! / 좋았어! … | `ceil(score/2)` 번 연속 맞히면 **−1** |
| 정답 · 맞췄지만 불안 | 사실 찍었음 / 운이 좋았다 … | **+1** |
| 오답 · 실수 | 아깝게 틀림 / 실수였어 … | **+1** |
| 오답 · 조금 어렵네 | 기억날 듯 말 듯 … | **+2** |
| 오답 · 완전 어렵네 | 처음 보는건데? … | **+3** |

- 버튼 문구는 단계별 풀에서 **매번 랜덤**으로 뽑아 대화하듯 보여주고, 아래에 가중치 배지를 작게 답니다.
- 노출 가중치 = **미출제 3 / 그 외 `1 + score`** (score 상한 10)
- **최근 5개 문제는 다시 출제되지 않습니다** (후보가 적으면 자동으로 줄어듭니다).
- **4문제마다 한 번은 "복습" 몫**으로, 이미 풀어 본 문제 중에서만 뽑습니다.
  이때의 가중치는 **마스터 직전(score 0 · 정답 1회) 8 / score 남은 문제 `1 + score` / 이미 마스터 1** 입니다.
  미출제 보너스 때문에 문제가 500개쯤 되면 한참을 풀어도 처음 보는 문제만 나오고,
  마스터는 같은 문제를 두 번 맞혀야 인정되므로 마스터율이 0에 붙어 있게 되는 걸 막습니다.
  마스터한 문제도 낮은 빈도로 계속 돌아와서, 잊어버린 건 다시 `score` 가 올라갑니다.

### API 호출 최적화

- 답안은 클라이언트에 쌓아 두었다가 **10문제마다 / 60초마다 / 화면 이탈·탭 종료 시**(`sendBeacon`) 배치 전송
- 서버는 **읽기 2회 + 쓰기 1회**로 진도와 일별통계를 함께 갱신
- 클라이언트는 계산된 점수가 아니라 **"무엇을 눌렀는지"(이벤트)** 를 보내므로, 두 탭에서 동시에 풀어도 기록이 덮어써지지 않고 합쳐집니다
- 전송에 실패하면 `localStorage`에 보관했다가 다음 기회에 재시도합니다

## 5. Vercel 배포

1. 저장소를 Vercel에 연결
2. **Settings > Environment Variables** 에 `.env.local` 과 같은 값 입력
   (`GOOGLE_PRIVATE_KEY` 는 JSON 의 값을 그대로 붙여넣으면 됩니다)
3. 배포 후 `/` 접속

> 서비스 계정 키 JSON 과 `.env*` 는 커밋되지 않도록 `.gitignore` 에 이미 등록되어 있습니다.

## 7. 코드 지도

```
src/
├─ app/                   화면 + API Route
│  ├─ page.tsx            과목 선택
│  ├─ study/              문제풀이
│  ├─ dashboard/          과목 대시보드
│  ├─ settings/           화면 설정
│  └─ api/                모든 Sheets 접근은 여기서만
├─ components/            UI (로고·차트·타임라인·캘린더·문제 상세·PIN 입력)
├─ hooks/                 배치 전송 큐, 학습시간 타이머, 로그인 상태
└─ lib/
   ├─ domain/             출제 알고리즘·압축 포맷·버튼 문구 (순수 함수)
   ├─ sheets/             Sheets API 클라이언트 + 한글 헤더 매핑
   ├─ repo/               시트별 읽기/쓰기
   └─ service/            배치 동기화 · 대시보드 집계
```
